# 08 · 数据与接口设计

---

## 1. 数据模型

### 1.1 核心实体

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| Campus（校区） | `id`, `name`, `aliases[]` | 取值来自知识库 `01_食堂基础信息`「所在校区」（当前**待填写**） |
| Canteen（食堂） | `id`, `campus_id`, `name`, `aliases[]`, `location`, `floor_layout_json`, `status` | `name` 取值 `一食堂`/`二食堂`/`三食堂` |
| Window（窗口） | `id`, `canteen_id`, `floor`, `name`, `type`（大锅菜/轻食/清真/面食…）, `is_halal` | `floor` 取自「楼层布局」（1 / 2） |
| Dish（菜品） | `id`, `name`, `category`, `base_price`, `spice_level`(0-3), `supply_period`, `feature_desc`, `tags[]`, `allergens[]`, `may_contain[]`, `nutrition_ref`, `verified_date`, `status` | 主数据；`feature_desc`=知识库「特色描述」 |
| MenuItem（每日供应） | `id`, `window_id`, `dish_id`, `date`, `meal_period`, `price`, `availability`, `verified_date`, `updated_at` | 每餐次一条，实时更新余量 |
| DishFeature（特色菜素材） | `id`, `dish_id`, `canteen_id`, `window_id`, `budget_tier`, `crowd_tag`, `reason`, `verified_date`, `status` | 来自知识库 `05_推荐素材` |
| Ticket（工单） | `id`, `category`, `canteen_id`, `window_id`, `description`, `contact_masked`, `status`, `created_at`, `sla_due_at` | 敏感字段加密 |
| UserProfile（画像） | `user_id_hash`, `taste[]`, `avoid[]`, `allergens[]`, `budget_default`, `favorite_canteen`, `consent_at` | 需授权，可删除；**不存位置与天气偏好以外的行踪数据** |
| Session（会话） | `thread_id`, `user_id_hash`, `started_at`, `last_active_at`, `summary` | 30 天清理 |
| AuditLog（审计） | `trace_id`, `thread_id`, `risk_flags`, `rules_hit`, `tool_calls`, `doc_ids`, `created_at` | 180 天 |
| WeatherCache（天气缓存） | `campus_id`, `payload_json`, `issued_at`, `source`, `cached_at` | **仅缓存，TTL 600s**，不进主业务库、不进知识库 |

### 1.2 关系简述

```
Campus 1─n Canteen 1─n Window 1─n MenuItem n─1 Dish
                                  Dish 1─n DishFeature
Ticket n─1 Canteen / Window
UserProfile 1─1 User(外部身份系统，仅存哈希)
Session n─1 UserProfile
```

### 1.3 数据来源与同步

| 数据 | 来源 | 同步方式 | 权威源 |
| --- | --- | --- | --- |
| 菜单/价格/余量/供应时段 | 食堂 POS / 菜品管理系统 | 上游 API 拉取 + Webhook 推送，60s 缓存 | **上游实时** |
| 食堂/窗口静态信息（位置、校区、楼层布局） | 知识库 `01_食堂基础信息` → `data/01_canteen_profile/` | ingestion 入 `canteen_profile`；枚举字典同步到 T1 | 知识库 |
| 营业时间 | 知识库 `03_营业与服务/营业时间.md` | ingestion 入 `canteen_rules`；**01 中的营业时间仅为摘要** | **03 营业时间表** |
| 规章制度（支付、饭卡、失物招领、投诉渠道） | 知识库 `03_营业与服务/食堂规章制度.md` | ingestion 入 `canteen_rules` | 知识库 |
| FAQ | 知识库 `04_FAQ` | ingestion 入 `canteen_faq` | 知识库 |
| 特色菜与按预算推荐 | 知识库 `05_推荐素材` | ingestion 入 `canteen_dish_features` | 知识库 |
| 食物成分 | 公开食物成分表 | ingestion 入 `nutrition_knowledge` | 公开资料 |
| 人流 | 刷卡/支付流水（脱敏聚合） | 小时级批处理 | 上游 |
| 天气 | 外部气象服务 | T4 实时拉取 + Redis 缓存 600s | 气象服务 |
| 饭卡余额 | 卡务系统 | **未接入**；统一按"暂未查到"处理 | — |

### 1.4 枚举字典（所有能力的取值口径必须一致）

| 枚举 | 取值 | 来源 |
| --- | --- | --- |
| `campus` | 待知识库填写；示例 `主校区` | 知识库 `01`「所在校区」 |
| `canteen` | `一食堂` / `二食堂` / `三食堂` | 知识库 `01` |
| `canteen` 别名 | 一食堂←"第一食堂""1 食堂""一餐"；二食堂←"第二食堂""2 食堂""二餐"；三食堂←"第三食堂""3 食堂""三餐" | 归一化层别名表（别名未命中记入高频未命中待补） |
| `floor` | `1` / `2` | 知识库 `01`「楼层布局」 |
| `meal_period` | `breakfast`(早餐) / `lunch`(午餐) / `dinner`(晚餐)；`night_snack` 保留但知识库无来源 | 知识库 `02`「供应时段」 |
| `spice_level` | `0` 不辣 / `1` 微辣 / `2` 中辣 / `3` 特辣 | 知识库 `02`「辣度」归一化 |
| `budget_tier` | `le_10`(≤10 元) / `10_15`(10–15 元) / `gt_15`(15 元以上) | 知识库 `05`「按预算推荐」 |
| `availability` | `in_stock` / `low` / `sold_out` | 上游 |
| `status`（语料） | `draft` / `published` / `expired` | 知识库 `00_知识库说明.md` |
| `ticket.category` | `complaint` / `suggestion` / `repair` / `food_safety` / `lost_and_found` | T3 |
| `weather_code` | `sunny` / `cloudy` / `rain_light` / `rain_heavy` / `snow` / `wind` / `haze` … | T4 |
| `alert.level` | `blue` / `yellow` / `orange` / `red`（**原样引用气象台**） | 气象台 |

> 上述字典以配置表形式下发到各能力，CI 校验各能力 `openapi.yaml` 中的 enum 与字典一致。

## 2. 对外 API

基础路径：`https://{host}/api/v1`；鉴权：校园统一身份 OAuth2 → JWT。

### 2.1 对话（SSE 流式）

`POST /api/v1/chat`

```json
{
  "thread_id": "th_01J9Z...",
  "message": "今天一食堂中午有啥？15 块以内",
  "channel": "wechat_mp",
  "client_meta": { "campus_hint": "主校区" },
  "stream": true
}
```

**SSE 事件序列**

| event | data | 说明 |
| --- | --- | --- |
| `start` | `{trace_id, thread_id}` | 立即返回 |
| `token` | `{delta}` | 流式文本 |
| `tool_call` | `{kind: skill\|tool, name, action, params}` | （可选）展示"正在查询…" |
| `tool_result` | `{kind, name, ok, degraded, source, summary}` | （可选）含天气等外部数据时附 `provider` 与 `issued_at` |
| `citation` | `{doc_id, title, source_url, updated_at}` | 引用来源 |
| `warning` | `{level, text}` | 风险提示 |
| `done` | `{usage, latency_ms, degraded}` | 结束 |
| `error` | `{code, message}` | 出错 |

### 2.2 其他接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/chat/confirm` | 人工确认（工单提交/取消），带 `thread_id` 恢复挂起的图 |
| `GET` | `/threads/{id}/messages` | 会话历史 |
| `DELETE` | `/users/me/data` | 删除个人数据（GDPR/个保法合规） |
| `POST` | `/feedback` | 点赞/点踩/答非所问（回流到知识库待办） |
| `GET` | `/menus?...` | 轻量直查（供前端看板，绕过 LLM） |

### 2.3 管理后台接口（需管理员权限）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/admin/knowledge/ingest` | 触发语料入库 |
| `GET` | `/admin/knowledge/runs` | 入库任务状态 |
| `GET` | `/admin/skills/health` | 各技能与工具的健康、熔断状态、降级级别分布 |
| `GET` | `/admin/traces/{trace_id}` | 回放完整 ReAct 轨迹 |
| `GET` | `/admin/guard/hits` | 护栏命中统计与待复核样本 |
| `POST` | `/admin/kill-switch` | 一键降级：停用某技能 / 停用工具调用 / 只保留 RAG |

## 3. 错误与降级对外表达

| 内部情况 | 用户可见 |
| --- | --- |
| 技能降级（缓存） | "（数据更新于 11:42，实际以窗口现场为准）" |
| 技能全失败 | "菜单服务暂时不可用，建议直接到窗口查看～" |
| 天气降级 / 全失败 | "（天气数据更新于 15:00，来源 xxx）" / "暂时查不到天气，先看下窗外吧～" |
| 官方气象预警 | 原样引用气象台口径 + "以学校官方通知为准" |
| RAG 无召回 | "这块我暂时没有可靠信息，建议咨询值班台（电话 xxx）" |
| 内容未核验（缺 `verified_date`） | "这个价格/时间还没有最新核验记录，建议到窗口确认～" |
| 护栏 BLOCK | 标准拒答话术（不解释检测细节，防绕过） |
| 图内部异常 | "刚刚卡了一下，能再说一次吗？" + 告警上报告警通道 |
| 触发人工确认 | 工单预览卡片 + "确认提交 / 修改 / 取消" |

## 4. 限流与配额

| 维度 | 阈值 |
| --- | --- |
| 单用户 | 20 条/分钟，200 条/天 |
| 单 IP | 100 条/分钟 |
| 全局 | 按模型 QPM 动态调整，超限时新会话排队并返回"稍等一下" |
| 单技能 | 由技能自身令牌桶保护，详见各技能 README |
| Token 预算 | 单会话上限 8k tokens，超出触发摘要压缩 |

## 5. 数据保留与清理

| 数据 | 保留期 | 清理方式 |
| --- | --- | --- |
| 会话原始消息 | 30 天 | 定时任务物理删除 |
| 会话摘要 | 90 天 | 物理删除 |
| PostgreSQL 过期 chunk | `expire_date` 后 30 天 | 软删除 → 物理删除 |
| 审计日志 | 180 天 | 归档后删除 |
| 用户画像 | 至用户删除或授权撤回 | 立即物理删除 |
| 工单 | 2 年 | 归档 |

## 6. 安全基线

- 全站 HTTPS；内部服务 mTLS 或网络隔离
- 技能服务不暴露公网，仅 `agent-server` 可访问
- 密钥走配置中心/环境变量，不入代码库
- 数据库（含 PostgreSQL 向量知识库）均校内私有化，访问白名单
- 管理后台强制二次认证 + 操作审计
