# 09 · 评测与可观测性

---

## 1. 评测分层

| 层级 | 评什么 | 方法 | 频率 |
| --- | --- | --- | --- |
| L1 检索 | Recall@5、MRR、无召回率、噪声率、**未核验误用率** | 标注集（q → 期望 doc_id） | 每次索引变更 |
| L2 能力调用 | 能力选择准确率（含 skill/tool 类型判断）、参数填充正确率、容错路径正确率、**可选特征缺失时的降级正确性** | 标注集（q → 期望 能力 + params） | 每次能力变更 |
| L3 生成 | 事实一致性（Faithfulness）、答案相关性、完整性、格式合规 | LLM-as-Judge + 人工抽检 | 每次提示词/模型变更 |
| L4 护栏 | 红队集零漏放、误拦率、风险提示注入率 | 规则断言 + 人工复核 | 每周全量 |
| L5 端到端 | 任务成功率、平均轮次、P95 延迟、成本/会话 | 端到端场景集（100+ 用例） | 每次发版 |
| L6 线上 | 点踩率、转人工率、追问率、无帮助反馈 | 埋点 | 实时看板 |

## 2. 评测集构成

| 集 | 规模 | 内容 |
| --- | --- | --- |
| 意图与路由集 | 300 条 | 覆盖 C1–C9 全部能力 + 闲聊 + 拒答 |
| **能力调用集** | 200 条 | 含歧义句、缺参数句、多能力组合句（菜单×天气、菜单×人流）；**新增**：技能 vs 工具的选择、天气类问法、参数枚举边界 |
| RAG 问答集 | 150 条 | 政策/FAQ/食品安全/食堂概览/特色菜，标注期望 chunk；**新增**：未核验与 expired 语料须走"暂未查到" |
| **护栏红队集** | 200 条 | 注入、越权、过敏绕过、医疗越界、舆情、辱骂、危机；**新增**：预警造假、位置索取、外部数据注入 |
| 容错集 | 60 条 | 注入超时/500/空数据/脏数据/限流，验证降级路径；**新增**：T4 四级降级、可选特征缺失不置 `degraded` |
| 端到端场景集 | 100 条 | 多轮对话脚本（含指代、纠错、确认）；**新增**：天气→推荐的跨能力协同链路 |

**阻塞规则**：红队集漏放 > 0、或端到端成功率下降 > 3pp → 阻断发布。

## 4. 可观测性

### 4.1 Trace（OpenTelemetry）

一次会话 = 一条 Trace，内部 Span：

```
guard_in ─ planner ─ react.round1(reason→act→observe) ─ react.round2 ─ reflector ─ guard_out
   └ rag.retrieve(domain, top_k, latency, hits, status_filter, recall_via)
   └ capability.call(kind, name, action, code, latency, retry, degraded, source, feature_flags)
```

每个 Span 记录：`trace_id`、`thread_id`、模型、token、延迟、错误码、`risk_flags`、降级标记。

### 4.2 指标（Prometheus）

| 指标 | 标签 |
| --- | --- |
| `chat_requests_total` | channel, route |
| `chat_latency_seconds` | p50/p95/p99 |
| `skill_calls_total` / `skill_errors_total` | kind(skill\|tool), name, action, code |
| `skill_circuit_state` | name |
| `skill_degraded_total` | name, level(L1-L4) |
| `capability_feature_missing_total` | name, feature（可选特征缺失次数，如 weather） |
| `rag_recall_total` / `rag_empty_total` | domain |
| `guard_hits_total` | category, level |
| `react_iterations` | — |
| `token_usage_total` | model, task |
| `guard_injection_blocked_total` | — |

### 4.3 日志

- 结构化 JSON；必带 `trace_id` / `thread_id` / `skill` / `code`
- **原始 query 不落盘**（仅脱敏后落盘），降低隐私风险
- 技能日志与智能体日志通过 `trace_id` 串联

### 4.4 告警

| 告警 | 条件 | 级别 |
| --- | --- | --- |
| 能力熔断 | 任一技能/工具进入 OPEN 状态 > 1 分钟 | P1 |
| 上游不可用 | 菜单服务连续 5 分钟 5xx | P1 |
| 外部配额耗尽 | 气象服务日配额使用 > 80% 或连续 429 | P2（自动切降级） |
| 护栏失效 | 护栏组件连续 10 次调用失败 | **P0**（自动切换保守模式：全部回答附加风险提示 + 禁用写操作） |
| 注入攻击 | 5 分钟内同一用户 3 次 | P2（安全通报） |
| 食安事件 | 命中 `FOOD_SAFETY_INCIDENT` | **P0**（即时通知值班人） |
| 危机干预 | 命中自伤意图 | **P0**（即时通知心理中心） |
| 成本异常 | 日 Token 成本超预算 120% | P2 |
| 质量下滑 | 点踩率 > 6% 持续 1 小时 | P1 |

## 5. 会话回放与归因

运营后台按 `trace_id` 可查看：

1. 原始（脱敏）提问与风险标记
2. 每一轮 ReAct 的 Thought / Action / Observation 原文
3. 每次技能调用的入参、出参、错误码、降级级别
4. RAG 召回的 chunk 全文、得分、是否被答案引用
5. 出站护栏的判定与注入的提示
6. Token 与耗时瀑布图

用途：Bad Case 归因（是检索没召回 / 工具选错 / 参数填错 / 护栏误拦 / 生成跑偏），并沉淀回对应评测集。
