# 05 · 能力清单与接口契约 ★

> 经 skill↔tool 评审后（见 `docs/00-项目结构.md §3`），能力按"确定性 / 显式参数 / 结构化结果 / 外部交互"四维划分：**2 个技能（S）**、**4 个工具（T）**。
>
> - **技能（Skill）** 位于 `skills/`，端口 `8100+`，需要模型推理与策略评估；
> - **工具（Tool）** 位于 `agent/tools/`，端口 `8200+`，确定性执行、显式参数、结构化返回。
>
> 其中 **T1 `canteen-menu-query` 为标杆工具**（完整契约与容错实现详见 [agent/tools/canteen-menu-query/README.md](../agent/tools/canteen-menu-query/README.md)），单独满足"至少 1 个独立封装能力"的硬性要求。

### 1.1 数据流铁律

| # | 规则 | 违反后果 |
| --- | --- | --- |
| D1 | **实时数据只走工具**：当前拥挤度、排队时长、饭卡余额、天气实况等实时量**不写入知识库**，只由 T2/T4 等工具经上游接口提供（知识库 `00_知识库说明.md` 明确规定） | 知识库返回过期实时值，造成事实错误 |
| D2 | **静态事实只走 RAG 或工具的结构化配置**：营业时间、价格、规章制度、FAQ、特色菜描述来自知识库召回或工具返回，禁止模型凭记忆生成 | 幻觉 |
| D3 | **冲突时以工具实时数据为准**，但须在回答中说明差异（"系统显示有，但公告说今日停供，以窗口现场为准"）；营业时间的**权威源是 `03_营业与服务/营业时间.md`**，各食堂概览中的营业时间仅为摘要 | 同一问题两种答案 |
| D4 | **未核验即"暂未查到"**：菜品/价格缺 `verified_date` 或状态非 `published` 时，按"暂未查到，建议到窗口确认"处理（对齐 `04_FAQ` 口径） | 用草稿数据作答 |
| D5 | **依赖分级**：skill→tool 分"强依赖（数据源，如 S1→T1）"与"可选特征（如 S1/T2→T4 天气）"两类。**仅可选特征**不可用时，退化为无该特征的基线并标注 `feature_missing`，**不置 `degraded=true`、不整体失败**；强依赖降级时技能继承其降级标记（见 `docs/00 §3.2`） | 级联雪崩 / 依赖语义不清 |
| D6 | **禁止 skill→skill、tool→skill**（见 `docs/00 §3.2`） | 依赖环 |
| D7 | 所有能力统一信封 `{request_id, code, message, data, meta}`、统一 5 位错误码、四级降级（见 `docs/04`） | 调用方无法统一容错 |

### 1.2 各能力的依赖声明

| 能力 | 强依赖（不可用则本能力失败） | 可选依赖（不可用则退化） |
| --- | --- | --- |
| T1 `canteen-menu-query` | 上游菜品系统 / 快照 / Redis | PostgreSQL 向量召回（L3） |
| T2 `crowd-forecast` | 脱敏聚合流水或历史基线 | T4 `weather-query`（降雨/气温作为客流特征） |
| T3 `feedback-ticket` | Postgres 工单库 | 通知通道（失败仅延迟通知，工单照常入库） |

| S1 `dish-recommender` | T1 `canteen-menu-query`（候选来源） | T4 `weather-query`（天气化排序）、`nutrition_analyzer`（粗估）、用户画像 |
| S2 `nutrition-analyzer` | 本地食物成分表 | PostgreSQL `nutrition_knowledge` 域 |

## T1 · `canteen-menu-query` 菜单查询（标杆工具）

> 完整契约、容错与测试见 [agent/tools/canteen-menu-query/README.md](../agent/tools/canteen-menu-query/README.md)。

### 功能
查询校园食堂**真实**的菜单数据：某天 / 某餐次 / 某食堂窗口供应哪些菜，含价格、辣度、供应时段、特色描述、过敏原标签、余量状态、营业时间。

### 触发示例
- "今天一食堂中午有啥？" / "二楼红烧肉还有吗？" / "15 块以内能吃啥？" / "食堂几点开门？"

### 动作列表

| action | 说明 |
| --- | --- |
| `query_dishes` | 按条件查菜品 |
| `get_dish_detail` | 单菜品详情（配料、过敏原、核验日期） |
| `get_canteen_info` | 食堂/窗口信息与营业时间 |
| `check_availability` | 指定菜品余量 |

### 入参示例（action=`query_dishes`）

```json
{
  "request_id": "req_01J9Z8X7K2M3N4P5Q6R7S8T9V0",
  "skill": "canteen-menu-query",
  "version": "1.2.0",
  "action": "query_dishes",
  "params": {
    "campus": "主校区",
    "canteen": "一食堂",
    "floor": 2,
    "date": "2026-09-08",
    "meal_period": "lunch",
    "keywords": ["鸡肉"],
    "filters": {
      "price_max": 15,
      "spice_level_max": 1,
      "tags_include": ["高蛋白"],
      "allergen_exclude": ["花生"],
      "available_only": true
    },
    "sort": { "field": "price", "order": "asc" },
    "pagination": { "page": 1, "page_size": 20 }
  },
  "context": { "user_id_hash": "u_9f2c1a", "trace_id": "tr_01J9Z", "deadline_ms": 800 }
}
```

**参数约束**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `campus` | string | ❌ | 枚举来自知识库 `01_食堂基础信息/*概览.md`「所在校区」；该字段当前**待填写**，实现时以配置字典为准（示例值 `主校区`） |
| `canteen` | string | ❌ | 枚举 `一食堂` / `二食堂` / `三食堂`；别名（"第一食堂""1 食堂""一餐"）由归一化层映射，见 `docs/08 §1.4` |
| `floor` | int | ❌ | 枚举 `1` / `2`（取自各食堂概览「楼层布局」）；越界返回 `40001` |
| `date` | string(date) | ❌ | 缺省 = 今天；仅支持今天 ~ +7 天，超出返回 `40001` |
| `meal_period` | enum | ❌ | `breakfast`/`lunch`/`dinner`（对应知识库早/午/晚）；`night_snack` 保留但**知识库无对应来源**，命中时不得臆造 |
| `filters.allergen_exclude` | string[] | ❌ | **硬过滤**，命中即不返回；枚举：花生/海鲜/牛奶/鸡蛋/麸质/大豆/坚果 |
| `filters.spice_level_max` | int 0-3 | ❌ | 0 不辣 / 1 微辣 / 2 中辣 / 3 特辣（知识库中文辣度在入库时归一化，见 `docs/06 §3.1`） |
| `filters.available_only` | bool | ❌ | 默认 true，过滤售罄 |

### 降级链与 SLA

| 级别 | 数据源 | 触发条件 | 用户可见提示 |
| --- | --- | --- | --- |
| L0 | 上游菜单 API | 正常 | 无 |
| L1 | Redis 缓存（TTL 60s） | 上游超时/5xx | "数据为 60 秒前" |
| L2 | 昨日同餐次快照 | 缓存未命中 | "参考昨日菜单，今日可能有调整" |
| L3 | PostgreSQL 向量召回 | 快照缺失 | "以下为历史/文档信息，可能不准确" |
| L4 | 兜底话术 | 全部失败 | "服务暂不可用，请到现场查看"（`code=50420`） |

- P95 延迟 ≤ 500ms（L0/L1）；可用性 ≥ 99.5%
- 超时 800ms，重试 2 次（仅读），熔断阈值：10s 内错误率 > 50% 且 ≥20 请求

## T2 · `crowd-forecast` 人流预测

> 完整契约见 [agent/tools/crowd-forecast/README.md](../agent/tools/crowd-forecast/README.md)。

| 项 | 内容 |
| --- | --- |
| 功能 | 预测各窗口未来 30/60 分钟的排队时长，给出错峰建议 |
| 触发 | "哪个窗口人少"、"现在去要不要排队"、"下雨天人会不会少点" |
| 数据源 | 历史刷卡/支付流水（脱敏聚合）+ 实时在店人数估计 + **可选**天气特征（T4） |

### 入参

```json
{
  "action": "forecast",
  "params": {
    "campus": "主校区", "canteen": "一食堂",
    "datetime": "2026-09-08T11:50:00+08:00",
    "horizon_minutes": 30,
    "with_weather": true
  }
}
```

> `with_weather=true` 时本工具内部调用 T4 `weather-query` 取降雨概率与气温作为**可选特征**；T4 不可用则自动置 `weather_used=false` 走无天气基线，**不置 `degraded`**（D5）。

### 出参（节选）

```json
{
  "code": 0,
  "data": {
    "windows": [
      { "window": "2F-轻食窗口", "queue_minutes": 2, "level": "low" },
      { "window": "1F-大锅菜", "queue_minutes": 12, "level": "high" }
    ],
    "best_time_to_go": "12:20 后预计回落",
    "advice": "现在 2 楼轻食窗口基本不用排队"
  },
  "meta": { "source": "model_v2", "degraded": false, "confidence": 0.78,
            "weather_used": true, "warnings": [] }
}
```

### 容错
- 实时流水缺失 → 用"同星期几 + 同时间段"历史基线（L2 降级，`degraded=true`）
- 置信度 < 0.6 时，回答中必须带"预测仅供参考"
- **不输出任何个人消费明细**，只输出聚合值（隐私合规）
- 天气特征缺失 → `weather_used=false` + `warnings:["weather_feature_missing"]`，**不计入降级**

## T3 · `feedback-ticket` 投诉建议工单（写操作）

> 完整契约见 [agent/tools/feedback-ticket/README.md](../agent/tools/feedback-ticket/README.md)。

| 项 | 内容 |
| --- | --- |
| 功能 | 将用户投诉/建议/报修/失物招领结构化为工单并送审 |
| 触发 | "我要投诉"、"建议增加素食窗口"、"空调坏了"、"我水杯丢了" |
| 特殊 | **必须经 LangGraph `interrupt` 人工确认后才真正提交** |

### 入参

```json
{
  "action": "create_ticket",
  "params": {
    "idempotency_key": "req_01J9Z...",
    "category": "complaint",
    "sub_category": "service_attitude",
    "campus": "主校区", "canteen": "一食堂", "window": "2F-轻食窗口",
    "occurred_at": "2026-09-08T11:30:00+08:00",
    "description": "窗口工作人员态度生硬",
    "urgency": "normal",
    "contact": { "phone_masked": "138****5678", "preferred_channel": "phone" },
    "attachments": []
  }
}
```

> `category` 枚举 `complaint` | `suggestion` | `repair` | `food_safety` | `lost_and_found`。`lost_and_found`（失物招领）是知识库 `03_营业与服务/食堂规章制度.md` 中明确的业务场景，工单落库同时应把值班台联系方式（取自知识库）一并返回给用户。

### 出参

```json
{
  "code": 0,
  "data": {
    "ticket_id": "TK20260908000123",
    "status": "pending_confirm",
    "preview": "工单预览：类别=服务态度投诉 / 地点=主校区一食堂2F轻食窗口 / 时间=2026-09-08 11:30",
    "estimated_response_hours": 24
  },
  "meta": { "degraded": false, "warnings": ["该工单需用户确认后提交"] }
}
```

### 容错与合规
- 幂等：`idempotency_key` 相同则直接返回首次结果，防重复提交
- 写操作**不重试**，失败返回具体原因（如"缺少联系方式"）交由主智能体追问
- 联系方式落库前脱敏存储，仅工单处理人可见
- 涉及"食物中毒""异物""变质"等关键词 → 自动置 `urgency=high` 并同步通知食堂值班人（人工告警通道）
- 用户取消 → `action=cancel_ticket`，状态置 `cancelled`

## T4 · `weather-query` 校园天气查询 ★新增

> 完整契约见 [agent/tools/weather-query/README.md](../agent/tools/weather-query/README.md)。

| 项 | 内容 |
| --- | --- |
| 功能 | 按校区/坐标查询**实况、短时与多日预报、官方气象预警**，并输出规则化派生的就餐出行提示 |
| 触发 | "今天下雨吗，去食堂要带伞吗"、"明天中午热不热"、"这种天适合吃点啥" |
| 数据源 | 外部公共气象服务（HTTP）+ Redis 缓存（TTL 10min）+ 本地校区坐标配置 + 季节气候基线 |
| 类型 | 只读；**不入库**（实时数据，遵循 D1） |

### 为什么是 Tool 而不是 Skill
给定"校区 + 时间"查天气属于**确定性读操作**：入参可枚举（校区白名单 / 时间范围 / 小时数），出参是固定 schema 的结构化 JSON，无需模型推理。涉及"这种天吃什么"的**搭配决策**仍归 S1 `dish-recommender`，本工具只提供天气事实与规则化提示。

### 动作列表

| action | 说明 |
| --- | --- |
| `get_current` | 当前实况（含体感、降水概率、AQI、UV） |
| `get_forecast` | 未来 1–72 小时或 1–7 天预报，支持按餐次切片（早/午/晚） |
| `get_alerts` | 官方气象预警（暴雨/高温/大风/寒潮等） |

### 入参示例

```json
{
  "request_id": "req_01J9Z8X7K2M3N4P5Q6R7S8T9V3",
  "skill": "weather-query",
  "version": "0.1.0",
  "action": "get_forecast",
  "params": {
    "campus": "主校区",
    "date": "2026-09-09",
    "meal_periods": ["lunch", "dinner"],
    "hourly_hours": 24
  },
  "context": { "user_id_hash": "u_9f2c1a", "trace_id": "tr_01J9Z", "deadline_ms": 800 }
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `campus` | string | ❌ | 校区白名单（与 T1 同一枚举字典），内部映射为预设经纬度；缺省取会话 `campus_hint` |
| `location` | `{lng,lat}` | ❌ | 显式坐标；**仅在用户明确授权定位时使用**，不落画像 |
| `date` | string(date) | ❌ | 缺省 = 今天；范围 [今天, +7 天]，越界 `40001` |
| `meal_periods` | enum[] | ❌ | `breakfast`/`lunch`/`dinner`，返回按餐次聚合的天气切片 |
| `hourly_hours` | int | ❌ | 1–72，默认 24 |
| `daily_days` | int | ❌ | 1–7，默认 3；与 `hourly_hours` 二选一优先 |

### 降级链与 SLA

| 级别 | 数据源 | 触发条件 | `meta.source` | 用户可见提示 |
| --- | --- | --- | --- | --- |
| L0 | 外部气象 API | 正常 | `upstream_api` | 无 |
| L1 | Redis 缓存（TTL 600s） | 超时 / 5xx / 限流 | `cache` | "数据更新于 {time}" |
| L2 | 最近一次成功结果（≤2h） | 缓存未命中 | `last_known` | "为 2 小时内的最近一次结果" |
| L3 | 本地季节气候基线（同月典型气温/降水） | 无历史 | `climatology` | "以下为该月份常年气候参考，非实况" |
| L4 | 兜底话术 | 全部失败 | `none` | `code=50420`："暂时查不到天气，建议看一眼窗外或留意学校通知" |

- P95 ≤ 400ms（L0/L1）；上游读取超时 800ms；重试 2 次（纯读幂等）；缓存 TTL 600s（天气变化慢，比菜单缓存更长效）
- 限流：外部 API 配额保护，单实例 50 QPS，超出走 L1

### 容错与合规
- **不入库、不进 RAG**：天气是实时数据，遵循 D1；也不写入用户画像
- **只传校区级坐标**：默认使用校区预设坐标，不采集用户精确位置；仅用户显式要求且会话内授权时才接受 `location`
- **官方预警原样引用**：`alerts` 中的类型、等级、标题、起止时间必须与气象台发布一致，**禁止改写等级、禁止自行发布或推测预警**；无官方预警时 `alerts` 返回空数组，不得编造
- **极端天气引导官方口径**：暴雨/高温/寒潮等场景必须追加"以学校官方通知为准"，不做避险承诺
- **健康相关交给护栏**："中暑了怎么办"属医疗场景，由 `guard_out` 注入就医指引，本工具只返回温湿度数值

### 错误码

| code | 含义 | 主智能体动作 |
| --- | --- | --- |
| `0` | 成功 | 正常使用，标注数据时间 |
| `40001` | 参数不合法（日期越界、校区非法） | 修正后重试 1 次 |
| `40002` | 未知 action | 改用合法 action |
| `40404` | 该校区无坐标配置 / 无该时段预报 | 询问校区或告知时段超出预报范围 |
| `42900` | 外部 API 配额耗尽 | 走 L1/L2，不重试 |
| `50010` | 内部错误 | 换表述或降级 |
| `50410` | 上游超时 | 已内部降级；仍失败走 L3 |
| `50420` | 全部降级失败 | 使用 `message` 兜底话术 |

## S1 · `dish-recommender` 个性化推荐

> 完整契约见 [skills/dish-recommender/README.md](../skills/dish-recommender/README.md)。

| 项 | 内容 |
| --- | --- |
| 功能 | 在给定约束（预算、忌口、过敏原、营养目标、口味、天气）下，从候选菜品中给出 **1 主菜 + 1 素菜 + 1 主食（+汤）** 的组合推荐，并给出推荐理由 |
| 触发 | "15 块吃啥好"、"减脂推荐一个"、"下雨天吃点啥" |
| 依赖 | **强依赖 T1 `canteen-menu-query`** 获取候选（skill→tool HTTP 调用，主智能体不感知）；**可选** T4 天气特征、S2 营养粗估 |

### 入参

```json
{
  "action": "recommend_combo",
  "params": {
    "campus": "主校区", "canteen": "一食堂", "date": "2026-09-08", "meal_period": "lunch",
    "budget": 15,
    "preferences": { "taste": ["清淡"], "avoid": ["香菜", "内脏"], "allergens": ["花生"] },
    "goals": { "type": "fat_loss", "calorie_max": 650 },
    "context_features": { "weather": "rain_light", "walk_comfort": "poor" },
    "diversity": { "exclude_dish_ids": ["d_10087"], "reason": "最近已吃过" },
    "top_k": 3
  }
}
```

> **预算分档**对齐知识库 `05_推荐素材/特色菜推荐.md` 的"按预算推荐"：`budget_tier` ∈ `≤10` / `10–15` / `>15`。用户说"十块钱能吃什么"时直接映射为 `budget_tier="≤10"`。
>
> **天气特征**由 S1 可选调用 T4 获取（或由主智能体透传），仅作为排序权重（雨天偏好就近食堂、热汤；高温偏好清淡）；T4 不可用时置 `weather_used=false` 继续求解（D5）。

### 出参（节选）

```json
{
  "code": 0,
  "data": {
    "combos": [
      {
        "rank": 1,
        "items": [
          { "dish_id": "d_10087", "name": "香煎鸡胸饭", "price": 12.0, "role": "main", "window": "2F-轻食窗口" },
          { "dish_id": "d_10233", "name": "清炒时蔬", "price": 3.0, "role": "veg", "window": "2F-轻食窗口" }
        ],
        "total_price": 15.0,
        "nutrition_estimate": { "kcal": 610, "protein_g": 38, "fat_g": 14 },
        "reasons": ["蛋白质 38g 达单餐目标", "总价刚好 15 元", "已排除花生与香菜"],
        "score": 0.91
      }
    ]
  },
  "meta": { "source": "realtime", "degraded": false, "weather_used": true }
}
```

### 容错
- 候选为空（预算过低/过滤过严）→ `code=40404` + `message` 建议放宽条件（"最低可行预算约 12 元"或"可看 10–15 元档"）
- T1 不可用时，降级为**基于 PostgreSQL 历史菜单/特色菜素材的近似推荐**，`degraded=true` + 提示"参考历史数据"
- 求解为启发式束搜索，超时 300ms 直接返回当前最优解（保证有结果）
- **硬约束任何降级路径都不得放宽**：过敏原过滤、忌口过滤

## S2 · `nutrition-analyzer` 营养分析

> 完整契约见 [skills/nutrition-analyzer/README.md](../skills/nutrition-analyzer/README.md)。

| 项 | 内容 |
| --- | --- |
| 功能 | 估算菜品/组合的能量与三大营养素，对照《中国居民膳食指南》给出**参考性**建议 |
| 触发 | "这顿多少卡"、"帮我看看蛋白质够不够" |
| 知识 | 内置食物成分表 + RAG 补充（PostgreSQL `nutrition_knowledge` 域） |

### 入参

```json
{
  "action": "analyze",
  "params": {
    "items": [
      { "name": "香煎鸡胸饭", "dish_id": "d_10087", "portion": "1份" },
      { "name": "清炒时蔬", "dish_id": "d_10233", "portion": "1份" }
    ],
    "user_profile": { "gender": "male", "age": 20, "weight_kg": 70, "activity_level": "moderate" },
    "goal": "fat_loss"
  }
}
```

### 出参

```json
{
  "code": 0,
  "data": {
    "totals": { "kcal": 610, "protein_g": 38.2, "fat_g": 14.5, "carb_g": 78.0, "sodium_mg": 1120 },
    "reference": { "recommended_kcal_per_meal": 700, "protein_target_g": 35 },
    "evaluation": [
      { "dim": "energy", "level": "ok", "text": "能量 610 kcal，低于单餐参考 700 kcal，符合减脂节奏" },
      { "dim": "sodium", "level": "high", "text": "钠含量偏高，建议搭配清淡汤品或减少酱汁" }
    ],
    "confidence": "medium",
    "disclaimer": "REQUIRED_NUTRITION_DISCLAIMER"
  },
  "meta": { "degraded": false, "source": "成分表+估算模型" }
}
```

### 容错与合规
- 菜品不在成分表 → 用同类菜品中位值估算并置 `confidence=low` + `meta.estimation_note`
- **出参必须带 `disclaimer`**，主智能体出站时强制展开为"以上为估算值，非医疗建议"
- 涉及疾病（糖尿病、肾病、痛风）→ 拒绝给具体饮食处方，只给通用原则 + 建议咨询校医院/营养师
