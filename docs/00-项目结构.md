## 2. 目录职责说明

| 目录                  | 职责                                                                                                                            | 关键约束                                                                                                                   |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `skills/`           | 保留为"技能"的能力——**需要模型推理/评估/引导**的开放性能力。每个技能有独立进程、独立端口、独立版本、独立 README 与 OpenAPI。                                                   | **禁止 skill→skill 直接调用**；技能只能被主智能体调度，或向下调用 `agent/tools/` 下的工具（skill→tool 允许）；禁止直接访问主库，须经自己的数据源适配器                      |
| `agent/tools/`      | 适合作"工具"的能力——**确定性执行、显式参数、结构化返回、与外部资源（HTTP/DB/Shell/FS）交互**。每个工具独立部署、独立版本，调用方为主智能体或上游技能。                                       | 工具调用失败不直接抛给上层，必须转成结构化 `ToolResult(ok/code/data)`；写操作类工具必须配合人工确认中断；**禁止 tool→skill 反向调用**（会产生环）；与技能一样遵循统一信封、5 位错误码、四级降级 |
| `agent/graph/`      | LangGraph 状态机。主图负责流程编排，ReAct 子图负责"推理—行动—观察"循环。                                                                                | 所有节点必须是纯函数式 `State → State`（便于测试与回放）                                                                                   |
| `agent/guardrails/` | 安全护栏。**策略与代码分离**，词表/话术放 `policies/`，支持热更新无需重启。                                                                                | 出站护栏为**强制节点**，任何分支都必须经过才能返回用户                                                                                          |
| `agent/rag/`        | PostgreSQL + pgvector 接入与检索链路（含图构建与社区摘要）。                                                                                                             | 所有回答的事实性内容必须带 `doc_id` + `chunk_id` 溯源；无召回必须走"知识不足"分支，禁止凭参数记忆作答                                                        |
| `agent/skills/`     | **技能**注册与统一调用（含 `registry.py` 与 `invoker.py`，对应 `agent/tools/` 下的 `registry.py` 与 `invoker.py` 一一对应）。这里是容错策略集中地（超时/重试/熔断/降级）。 | 技能 / 工具调用失败**不允许**直接抛给 LLM 崩溃，必须转成结构化 `SkillResult(error)` / `ToolResult(error)` 交回 ReAct 循环自主决策                       |
| `agent/memory/`     | 短期会话 + 长期用户画像。                                                                                                                | 过敏、疾病、宗教饮食属**敏感个人信息**，写入前必须取得明示同意，且支持一键删除                                                                              |
| `data/`             | 知识库原始语料（来自「食堂干饭助手-知识库」），是 RAG 的唯一事实来源。                                                                                        | 只摄入 `status=published` 的语料；`draft` 不入库、`expired` 仅历史追溯；必须带 `verified_date`（最后核验日期）、来源与审核人；下线走软删除 + 索引版本递增              |
| `eval/`             | 评测资产。                                                                                                                         | 新版本上线前必须通过回归集；红队集失败率 > 0 即阻断发布                                                                                         |

## 3. Skill 与 Tool 的划分原则

> 本节由最近一次能力评审沉淀。所有原 `skills/` 下条目按以下四条维度逐项判定，决定其作为 **skill（技能）** 还是 **tool（工具）** 留存。

| 维度   | 偏向 tool                | 偏向 skill            |
| ---- | ---------------------- | ------------------- |
| 执行性质 | 固定逻辑、无需规划，单次调用即可完成     | 需要模型推理、策略选择、迭代评估    |
| 参数调用 | 显式结构化参数（schema 校验）     | 自然语言/隐含语义（需 LLM 抽取） |
| 返回结果 | 可被程序消费的结构化 JSON        | 叙事性 / 多方案 / 含建议与解释  |
| 环境交互 | HTTP/DB/FS/Shell 等外部资源 | 与 LLM 工作流交互         |

### 3.1 逐项判定结论

| 原 skills/ 能力         | 确定性 | 显式参数 |       结构化结果      |      外部交互      | 结论                | 核心理由                                                                     |
| -------------------- | :-: | :--: | :--------------: | :------------: | ----------------- | ------------------------------------------------------------------------ |
| `canteen-menu-query` |  强  |   ✅  |         ✅        | HTTP / 缓存 / 上游 | → **tool**        | 给定条件查表过滤，逻辑固定，schema 入出参固定，适合程序化直接调用                                     |
| `dish-recommender`   |  弱  |  部分  |   JSON + 评分与理由   |     内部 HTTP    | → **保留 skill**    | 内部束搜索 + 启发式评分 + 推荐理由生成 + 空候选建议放宽，依赖模型理解用户偏好与目标                           |
| `nutrition-analyzer` |  中  |  部分  | JSON + 估算 + 评估维度 |   成分表 / 估算模型   | → **保留 skill**    | 含估算置信度判断、能量/钠等维度评估策略、疾病合规检测、降级分支；不是单纯查表                                  |
| `crowd-forecast`     |  强  |   ✅  |         ✅        |    模型服务 / 基线   | → **tool**        | 给定时间/食堂返回各窗口排队时长与等级，输入输出可参数化                                             |
| `feedback-ticket`    |  强  |   ✅  |         ✅        |    DB / 通知通道   | → **tool**        | 写操作逻辑确定（idempotency_key、分类枚举、字段校验），可程序化调用；写后仍需 LangGraph 人工确认            |
| `weather-query`      |  强  |   ✅  |         ✅        |  外部气象 API / 缓存 | → **tool（新增）**    | 给定校区+时间查实况/预报/预警，纯读、入参可枚举、输出结构化，无需模型推理；仅把"吃什么"的搭配判断留给 `dish-recommender` |
| `_template`          |  —  |   —  |         —        |        —       | → **保留**（脚手架，非能力） | 元模板，归类为脚手架而非能力实体，与 `tools/_template` 并列保留                                |

### 3.2 调用方向（禁止成环）

```
        主智能体（LangGraph ReAct）
          │  skill_call          │  tool_call
          ▼                      ▼
      skills/  ──skill→tool──►  agent/tools/  ──► 外部资源（上游 API / DB / 缓存）
          ✗ 禁止 skill→skill        ✗ 禁止 tool→skill
```

| 调用方向      | 是否允许 | 说明                                                                               |
| --------- | ---- | -------------------------------------------------------------------------------- |
| 主智能体 → 技能 | ✅    | ReAct 自主选择                                                                       |
| 主智能体 → 工具 | ✅    | ReAct 自主选择                                                                       |
| 技能 → 工具   | ✅    | 如 `dish-recommender` 调 `canteen-menu-query`；`crowd-forecast` 可选调 `weather-query` |
| 技能 → 技能   | ❌    | 会造成依赖环与故障级联                                                                      |
| 工具 → 技能   | ❌    | 工具必须保持无状态与确定性                                                                    |

> **依赖分级原则**（skill→tool 两类，务必区分）：
>
> | 类型           | 例子                                              | 工具不可用时技能的行为                                                                    |
> | ------------ | ----------------------------------------------- | ------------------------------------------------------------------------------ |
> | **强依赖（数据源）** | S1 `dish-recommender` → T1 `canteen-menu-query` | 技能继承 T1 的降级结果；T1 完全不可用时技能返回 `50420` 兜底话术                                       |
> | **可选特征**     | S1/T2 → T4 `weather-query`                      | 退化为无该特征的基线结果，`meta.warnings` 标注 `feature_missing`，**不置 `degraded=true`、不整体失败** |
>
> 目的：避免"非关键工具抖动 → 主链路雪崩"。新增 skill→tool 调用必须在 README 中声明属于哪一类。

| 分支           | `feat/skill-xxx`、`fix/guard-xxx` | `feat/skill-crowd-forecast` |
