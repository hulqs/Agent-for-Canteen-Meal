# 10 · 实施计划与部署

---

## 1. 五阶段实施计划

| 阶段 | 目标 | 交付物 | 关键验收 |
| --- | --- | --- | --- |
| **P0 地基**（1 周） | 跑通最小闭环 | 目录结构、PostgreSQL + pgvector 实例、LangGraph 主图骨架（guard_in → planner → respond → guard_out）、空 Registry | 能对话，能拒答，护栏生效 |
| **P1 工具先行**（2 周） | 落地硬性要求① | T1 `canteen-menu-query` 完整实现（OpenAPI + 信封 + 容错 + 测试），Registry 接入，模型可自动调度 | 能力选择准确率 ≥ 90%；注入超时/500 能降级不崩 |
| **P2 知识增强**（2 周） | 落地硬性要求③ | `kb` schema + 7 个知识域分区建库、知识库目录→`data/`→PostgreSQL 的 ingestion 流水线（含状态门控与归一化）、向量 + 全文 + 图谱混合检索 + Rerank、图构建与社区摘要、引用与溯源 | Recall@5 ≥ 90%；无召回/未核验走标准话术 |
| **P3 护栏与闭环**（2 周） | 落地硬性要求④ | 四道护栏、风险提示模板、T3 工单 + 人工确认中断、审计与告警 | 红队集零漏放；过敏感知 100% 注入 |
| **P4 打磨上线**（2 周） | 体验与稳定 | S1/S2 两个技能 + T2/T4 两个工具、流式输出、评测集全量回归、灰度发布 | 端到端成功率 ≥ 92%；P95 ≤ 3s |

> 并行项：知识库语料整理与审核（后勤处）从 P0 就开始，是 P2 的前置依赖，务必提前启动。**注意**：知识库当前为模板状态（食堂位置、价格、菜单多为"待填写"），P2 前至少补齐一食堂的概览与菜品表才能验证链路。

> **P4 内 T4 `weather-query` 的落地顺序**：先接外部气象服务与缓存（L0/L1），再接季节气候基线（L3）与兜底话术（L4），最后把天气作为**可选特征**接入 T2 与 S1，并验证"天气不可用时不影响主链路"。

## 2. 部署拓扑（生产）

```
                    ┌──────────────┐
   微信/网页 ──────► │  Gateway      │  (2 副本)
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │ agent-server │  (4 副本, LangGraph)
                    └──┬────────┬──┘
                       │        │
        ┌──────────────▼──┐  ┌──▼────────────────────────────────┐
        │ (知识库并入      │  │  Capabilities（各自副本）           │
        │  Postgres kb     │  │  Skills 8101–8102                  │
        │   schema)        │  │  Tools  8201–8204（含外部气象出口） │
        └─────────────────┘  └──┬──────────────┬──────────────────┘
                             └──┬──────────────┬──────────────────┘
                                │
        ┌───────────┬───────────┼───────────┬──────────┐
        ▼           ▼           ▼           ▼          ▼
     Redis      Postgres    上游食堂API   校统一身份  外部气象服务
    (缓存/会话) (业务/审计/  (菜单/流水)    (OAuth)   (仅 T4 出站)
                kb 向量知识库)
```

> **网络策略**：工具与技能不暴露公网，仅 `agent-server` 可访问；**唯一例外**是 T4 `weather-query` 需要出站访问外部气象服务，须走出口白名单 + 独立 NAT，且不携带任何用户标识。

> **知识库底座**：GraphRAG 的向量、全文、图谱数据统一落在 **Postgres 实例的 `kb` schema**，与业务库同实例；pgvector 扩展提供 HNSW 向量索引，`tsvector` 提供中文全文，`entity/relation/community` 表承载图谱。详见 docs/06、docs/11。

**资源建议（单校区 5 千人规模）**

| 组件 | CPU | 内存 | 副本 | 说明 |
| --- | --- | --- | --- | --- |
| agent-server | 2C | 4G | 4 | 主要开销在模型调用等待，非 CPU 密集 |
| 技能/工具各自 | 1C | 1G | 2 | 菜单工具可扩到 4；天气工具 1 副本即可（缓存命中率高） |
| Redis | 1C | 2G | 1 | — |
| Postgres | 4C | 8G | 1（主从） | 业务 + kb 知识库同实例；HNSW 索引构建建议 `maintenance_work_mem ≥ 2GB`；< 30 万 chunk 单机足够 |

## 3. 环境配置

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| dev | 本地开发 | 样例菜单 + 本地 PostgreSQL + pgvector |
| staging | 联调与评测 | 脱敏生产数据快照 |
| prod | 线上 | 真实数据，变更需审批 |

**配置项（示例清单，值不入代码库）**

| 配置 | 说明 |
| --- | --- |
| `LLM_MAIN_MODEL` / `LLM_LIGHT_MODEL` | 主模型与护栏小模型 |
| `LLM_API_BASE` / `LLM_API_KEY` | 校内或合规的模型网关 |
| `PG_HOST` / `PG_PORT` / `PG_DATABASE` / `PG_KB_SCHEMA` | 向量知识库连接（`kb` schema） |
| `EMBED_MODEL_KEY` / `EMBED_DIM` | 当前 embedding 模型键与维度（如 `bge-m3@v1.5` / 1024） |
| `SKILL_REGISTRY_URL` / `SKILL_TIMEOUT_MS` | 能力注册与默认超时 |
| `WEATHER_API_BASE` / `WEATHER_API_KEY` / `WEATHER_PROVIDER` | 外部气象服务（仅 T4 使用，出站白名单） |
| `WEATHER_CACHE_TTL_SECONDS` | 默认 600 |
| `GUARD_MODE` | `strict` / `balanced` / `audit_only` |
| `MAX_REACT_ITERATIONS` | 默认 6 |
| `DATA_RETENTION_DAYS` | 默认 30 |

## 4. 发布策略

| 策略 | 说明 |
| --- | --- |
| 灰度 | 先 5% 用户 → 30% → 100%，每档观察 24 小时 |
| 技能独立发布 | 技能版本独立灰度，主智能体按 `version` 路由；不兼容变更保留旧版 30 天 |
| 提示词版本化 | 提示词与代码同仓、同版本、可回滚；A/B 对比用评测集打分 |
| 一键降级（Kill Switch） | ① 停用某技能 ② 全局禁用工具只留 RAG ③ 只保留拒答与人工引导 |
| 回滚 | 镜像标签回滚；数据库变更必须可前向兼容 |

## 5. 风险登记

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 上游菜单数据质量差（价格错、余量不准） | 用户信任受损 | 数据校验 + 脏数据隔离 + 强制"以现场为准"提示 + 反馈闭环 |
| 知识库为模板状态，价格/位置大量"待填写" | 无召回率高、答非所问 | 未核验即"暂未查到"；上线前至少补齐一食堂；高频未命中周报驱动补录 |
| 营业时间在知识库两处重复且不一致 | 同一问题两答案 | 权威源裁定（`03_营业与服务/营业时间.md`）+ 检索层 primary 优先 |
| 菜名/窗口/食堂别名口语化导致检索失败 | 召回低 | 别名表 + 查询改写 + BM25 混合检索 + 别名未命中待补清单 |
| 外部气象服务不稳定或配额耗尽 | 天气问答不可用 | T4 四级降级 + 可选特征非强依赖（不影响主链路） |
| 模型把"知识库里的旧菜单"当今天的 | 事实错误 | metadata 强过滤 `date` + 冲突时以技能实时数据为准 + 出站核验 |
| 过敏场景漏提示 | **安全事故** | 硬过滤在技能层（不依赖模型）+ 出站模板强制注入 + 红队集周检 |
| 提示注入 | 越权/泄密 | 三层防御 + 工具白名单 + 人工确认 |
| 模型服务不稳定 | 整体不可用 | 多模型网关 + 降级到小模型 + 保守模式兜底 |
| 成本失控 | 预算超支 | 小模型护栏 + 缓存 + Token 预算与告警 |
| 语料审核滞后 | 知识库陈旧 | 入库审核 SLA + 过期自动失效 + 高频未命中周报 |
