# 10 · 实施计划与部署

---

## 1. 五阶段实施计划

| 阶段 | 目标 | 交付物 | 关键验收 |
| --- | --- | --- | --- |
| **P0 地基**（1 周） | 跑通最小闭环 | 目录结构、ChromaDB 本地实例、LangGraph 主图骨架（guard_in → planner → respond → guard_out）、空 Registry | 能对话，能拒答，护栏生效 |
| **P1 技能先行**（2 周） | 落地硬性要求① | `canteen-menu-query` 完整实现（OpenAPI + 信封 + 容错 + 测试），Registry 接入，模型可自动调度 | 工具选择准确率 ≥ 90%；注入超时/500 能降级不崩 |
| **P2 知识增强**（2 周） | 落地硬性要求③ | 5 个 Collection 建库、ingestion 流水线、混合检索 + Rerank、引用与溯源 | Recall@5 ≥ 90%；无召回走标准话术 |
| **P3 护栏与闭环**（2 周） | 落地硬性要求④ | 四道护栏、风险提示模板、工单技能 + 人工确认中断、审计与告警 | 红队集零漏放；过敏感知 100% 注入 |
| **P4 打磨上线**（2 周） | 体验与稳定 | 其余 3 个技能、流式输出、评测集全量回归、灰度发布 | 端到端成功率 ≥ 92%；P95 ≤ 3s |

> 并行项：知识库语料整理与审核（后勤处）从 P0 就开始，是 P2 的前置依赖，务必提前启动。

## 3. 环境配置

| 环境 | 用途 | 数据 |
| --- | --- | --- |

## 4. 发布策略

| 策略 | 说明 |
| --- | --- |
| 灰度 | 先 5% 用户 → 30% → 100%，每档观察 24 小时 |
| 技能独立发布 | 技能版本独立灰度，主智能体按 `version` 路由；不兼容变更保留旧版 30 天 |
| 提示词版本化 | 提示词与代码同仓、同版本、可回滚；A/B 对比用评测集打分 |
| 一键降级（Kill Switch） | ① 停用某技能 ② 全局禁用工具只留 RAG ③ 只保留拒答与人工引导 |
| 回滚 | 镜像标签回滚；数据库变更必须可前向兼容 |

## 5. 风险登记

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 上游菜单数据质量差（价格错、余量不准） | 用户信任受损 | 数据校验 + 脏数据隔离 + 强制"以现场为准"提示 + 反馈闭环 |
| 菜名/窗口口语化导致检索失败 | 召回低 | 别名表 + 查询改写 + BM25 混合检索 |
| 模型把"知识库里的旧菜单"当今天的 | 事实错误 | metadata 强过滤 `date` + 冲突时以技能实时数据为准 + 出站核验 |
| 过敏场景漏提示 | **安全事故** | 硬过滤在技能层（不依赖模型）+ 出站模板强制注入 + 红队集周检 |
| 提示注入 | 越权/泄密 | 三层防御 + 工具白名单 + 人工确认 |
| 模型服务不稳定 | 整体不可用 | 多模型网关 + 降级到小模型 + 保守模式兜底 |
| 成本失控 | 预算超支 | 小模型护栏 + 缓存 + Token 预算与告警 |
| 语料审核滞后 | 知识库陈旧 | 入库审核 SLA + 过期自动失效 + 高频未命中周报 |
