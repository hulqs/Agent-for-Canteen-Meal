## 4. 响应示例

```json
{
  "request_id": "req_ULID",
  "code": 0,
  "message": "ok",
  "data": { "【待填】": "【待填】" },
  "meta": {
    "latency_ms": 0,
    "skill_version": "0.1.0",
    "data_version": "",
    "source": "upstream_api | cache | snapshot | vector_recall | none",
    "degraded": false,
    "cache_hit": false,
    "warnings": []
  }
}
```

> 信封规则（不可改）：
>
> - 业务失败 = **HTTP 200 + `code != 0`**；只有进程不可用才用 5xx
> - `meta.degraded=true` 时主智能体必须向用户披露
> - `message` 必须给出**可行动**的信息，失败时给出可直接念给用户的话术

## 5. 容错设计

### 降级链

| 级别 | 数据源         | 触发条件   | 用户可见提示       |
| -- | ----------- | ------ | ------------ |
| L0 | 上游实时        | 正常     | 无            |
| L1 | Redis 缓存    | 超时/5xx | "数据有延迟"      |
| L2 | 历史快照        | 缓存未命中  | "参考历史数据"     |
| L3 | ChromaDB 召回 | 快照缺失   | "可能不准确"      |
| L4 | 兜底话术        | 全部失败   | `code=50420` |

### 参数

| 项       | 值                                 |
| ------- | --------------------------------- |
| 连接/读取超时 | 300ms / 800ms                     |
| 重试      | 读 2 次（指数退避+抖动）；**写操作不重试**         |
| 熔断      | 10s 窗口、≥20 请求、错误率 >50% → OPEN 30s |
| 缓存 TTL  | 【待填】                              |
| 限流      | 【待填】QPS                           |
| 幂等      | 写操作必带 `request_id` 作为幂等键          |

## 7. 错误码

| code    | 含义        | 主智能体动作       |
| ------- | --------- | ------------ |
| `0`     | 成功        | 正常使用         |
| `40001` | 参数校验失败    | 修正后重试 1 次    |
| `40002` | 未知 action | 改用合法 action  |
| `40301` | 越权        | 拒绝并说明        |
| `40404` | 无数据       | 放宽条件 / 告知用户  |
| `42900` | 限流        | 退避后重试 1 次    |
| `50010` | 内部错误      | 换工具或降级       |
| `50410` | 上游超时      | 已降级；仍失败走 RAG |
| `50420` | 上游不可用     | 直接用兜底话术      |
| `50300` | 熔断中       | 直接降级         |

## 8. 可观测性与测试

| 项    | 要求                                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------------ |
| 日志   | 结构化 JSON + `trace_id` / `code` / `latency_ms` / `source`                                                     |
| 指标   | `skill_calls_total{action,code}`、`skill_latency_seconds`、`skill_degraded_total{level}`、`skill_circuit_state` |
| 健康检查 | 上游不健康时自身仍返回 200，仅标记 `upstream: "down"`                                                                       |
| 契约测试 | 每个 action：正常 / 边界 / 非法参数                                                                                     |
| 故障注入 | 超时、500、空数据、脏数据、限流、缓存不可用                                                                                      |
| 性能   | 目标 QPS 下 P95 ≤ 500ms，错误率 < 1%                                                                                |
